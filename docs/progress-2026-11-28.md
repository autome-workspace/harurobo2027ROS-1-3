# 2026-11-28 開発記録

Ubuntu 24.04 / ROS 2 Jazzyで、Control Center、カメラ・LiDAR較正、AMT102-CAN受信、エンコーダーによる指定距離移動を更新した。前日の記録は[2026-11-27](progress-2026-11-27.md)を参照。

## 今日追加・修正した機能

### カメラ・LiDAR較正と自動接近

- 少数点較正（推定4点＋独立検証1点）を追加。分布・誤差・解の安定性の検査は維持。
- LiDARの使用角度範囲と候補の最低点数をGUIから変更可能にした。元の `/scan` は変更しない。
- 「解がありません」の診断を改善し、暫定解で誤差の大きいサンプルIDを表示。
- 保存した外部較正・認識条件を既存のボール位置推定と自動接近へ接続。
- 自動接近を足回り駆動の選択機能に統合し、独立した非駆動確認の起動項目を整理。
- CANがDOWNの場合の足回り起動を拒否。RVizの通常表示に `/scan` の点群を設定。

利用者から較正完了の報告があった一方、実機移動でカメラの仮固定がずれたとの報告もあった。カメラを固定し直した後は再較正が必要。今回、自動回収の精度・繰り返し動作まで確認したという意味ではない。

### AMT102-CANエンコーダー2台の受信

独立したROSパッケージ `real/src/amt102_can/` を追加した。

- モーター側の `can0` と別の、WeAct側 `slcan0` でCH1・CH2を受信。
- GUIからエンコーダー側SLCANの作成・UP操作と読取開始を実行。既存のモーターCANを操作しない。
- uint24の位置をbig-endianで復号し、1回転65536の規格位置から角度・相対回転数を計算。周回と受信基準リセットを扱う。
- 通常データ用SocketCANフィルターにCAN_ERR_FLAGを含めないよう修正。
- 異常詳細は項目5の読出しだけを送信し、再起動履歴のみの状態と他の異常を分離。設定書込みや履歴消去はしない。
- `/encoders/state` と各CHのJointStateを配信。GUIへの通知はROSグラフ探索から分離し、既定50Hzで表示を更新。
- 専用RVizの矢印・角度・回転数表示を追加。表示用座標系は実機のオドメトリTFと分離。
- 切断・古い受信値・読取プロセスの再起動を識別する。

このPCではCH1・CH2の約200Hz受信、再起動履歴bitのみの異常詳細、手回し時の値の変化を確認した。利用者からGUI・RVizで読み取れたとの報告があった。

### エンコーダー指定距離移動

既存の足回り・独立ウォッチドッグを再利用し、距離制御部分を別モジュールとして追加した。

| 項目 | 設定・動作 |
| --- | --- |
| 前後計測 | CH2、値の減少が前進 |
| 左右計測 | CH1、値の増加が左移動 |
| 計測車輪 | 直径50mm、エンコーダーと直結。1回転は約157.08mm |
| 操作 | 中立でL1を離して押し直し、L1保持＋十字キー |
| 進行方向 | 距離PID。初期P=2.0、I=0.1、D=0.25 |
| 速度 | 初期上限250mm/s、加減速度400mm/s² |
| 低速失速対策 | 最低移動速度の初期値30mm/s。GUIで変更、0で無効化 |
| 横ずれ補正 | エンコーダーによるPD。初期P=2.0、D=0.25、補正上限80mm/s |
| 横ずれ停止 | 初期許容50mm、GUIで5〜100mm。既存PC設定は保持 |
| 到達 | 進行方向の残距離5mm以内、横ずれ5mm以内で完了 |

距離・方向・速度・ゲインは「指定距離移動設定」から利用者別YAMLに保存する。合成した並進速度と加速度を制限し、自動接近との同時有効化を拒否する。横ずれPDは開始位置を通る直線へ戻す。前後移動の左右ずれ、左右移動の前後ずれの両方に対応し、目標距離到達後も必要なら横方向を調整する。

利用者から基本移動が動作したとの報告があった。その後の速度向上・横ずれ補正を含む最終版は模擬データで検証したもので、実機での最終ゲイン、制動距離、繰り返し精度は未確認。

### 停止判定と診断

- 指定距離移動だけが生のL1値で中止していた箇所を、既存の100ms連続OFF判定へ統一。
- 150msのコントローラー入力途絶、IMU・エンコーダーの鮮度監視、独立ウォッチドッグは維持。
- L1解除、スティック操作、逆方向移動、横ずれ超過、姿勢変化、進捗停止、時間超過を区別して表示。
- 「L1を離して再開」は再操作手順として表示し、停止理由と混同しないよう変更。
- PID減速時の低い指令速度による失速を仮想摩擦モデルで再現し、最低速度設定を追加。実機の摩擦係数を測定したものではない。
- 進捗は目標点までの距離の改善で判定し、終端の横方向調整も扱う。動けない場合は中止し続ける。

機体の姿勢補正はIMUを使う。エンコーダーの取付オフセットは未較正のため、回転を伴う位置推定には未対応で、約1.7°を超える姿勢変化では中止する。GUIの停止ボタンやソフトウェア監視は物理非常停止の代わりにはならない。

### IMUポートの固定

このPCのIMU起動設定を `/dev/ttyACM*` の番号指定ではなく、DM-IMU-L1の `/dev/serial/by-id/` へ変更した。受信専用ノードで `/imu/data` を20件受信し、`imu_link` を確認した。設定はPC内に保存し、機器固有のシリアル番号を共有初期値には固定しない。

## 起動・反映手順

```bash
source /opt/ros/jazzy/setup.bash
colcon build --base-paths real/src --packages-select amt102_can camera_lidar_calibration --symlink-install
source install/setup.bash
```

Control Centerは既存のUbuntuアプリ登録から起動できる。エンコーダーの手順は[AMT102 README](../real/src/amt102_can/README.md)、指定距離移動・調整は[Control Center README](../ros2_control_center/README.md)、較正は[較正README](../real/src/camera_lidar_calibration/README.md)を参照。

実行中の制御へ変更を適用しない。足回りを停止し、GUIを再起動して設定画面を更新してから、足回りを再起動する。方向は各機体で手押し確認して設定する。上表の方向は今回の機体で利用者が確認したもの。

## 検証結果

- AMT102と較正パッケージのpytest：36件成功、1件スキップ。スキップはシステムPythonにPySide6がないためのGUIテスト。
- 既存PySide6仮想環境で較正GUIテスト：1件成功。
- Control Centerの15種類の確認スクリプトに成功。距離換算、距離PID、横ずれPD、摩擦・失速、GUI設定保存、受信異常、L1判定、監督プロセス終了、エンコーダー表示、SLCAN操作、CAN起動拒否、自動接近統合、較正結果の利用、デモ起動停止、ROS→Qtの表示経路を確認した。
- 距離PIDは60条件、横ずれPDは16条件の模擬走行で確認。摩擦モデルは4方向で対策前の失速と対策後の到達を比較した。
- ROS→監視プロセス→Qtの表示経路は、模擬8chと大きいJSONを使い、1.2秒で60種類の値更新、受信停止と復帰を確認。
- `amt102_can` と `camera_lidar_calibration` のcolconビルド成功。Python構文・Git差分検査に成功。
- デモテストが実際のPC設定を読む問題を修正し、一時設定ファイルによる独立実行へ変更した。実機モードの設定は書き換えない。

テストは別ROSドメイン、模擬CAN、模擬プロセスを使用する。今回の最終検証で実機のモーターを起動するテストは行っていない。
