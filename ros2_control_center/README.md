# ROS 2 Control Center

Ubuntu 24.04 / ROS 2 Jazzy向けの日本語ローカル管理GUIです。PySide6の画面、プロセス管理、ROS状態監視を分離しています。

## 起動と登録

リポジトリのルートから実行します。

```bash
bash ros2_control_center/install.sh
```

Ubuntuのアプリ一覧から「ROS 2 Control Center」を起動できます。デスクトップにも登録する場合は `--desktop` を付けます。インストーラーはユーザー用の仮想環境を作成し、システムPythonを上書きしません。ROS関連パッケージは各ワークスペースで事前にビルドしてください。

開発時は次の方法でも起動できます。

```bash
"$HOME/.local/share/ros2-control-center/venv/bin/python" ros2_control_center/main.py
```

## 利用できる機能

- 実機・Gazebo・デモの切り替え、個別起動停止、依存順の一括起動停止。
- 二重起動防止、管理外ノード検出、終了コードとトピック受信を使った状態表示。
- 管理中のプロセス群をSIGINT、SIGTERM、SIGKILLの順で停止。
- プログラム別・統合ログ、検索、保存、保持件数の制限。
- USB・シリアル機器の表示とSocketCAN診断、認証画面を経由したCANのUP操作。
- PS4手動操作と既存のボール自動接近処理の起動。
- カメラ撮影設定、内部較正、[カメラ・LiDAR外部較正](../real/src/camera_lidar_calibration/README.md)と較正後の画像投影。

共有の起動コマンド・依存関係は `config/programs.yaml` にあります。PC固有のデバイス、撮影設定、較正ファイルなどは `$XDG_CONFIG_HOME/ros2-control-center/local.yaml`（未指定時は `~/.config/ros2-control-center/local.yaml`）に保存します。例は `config/local.example.yaml` を参照してください。管理・監視機能の全項目が実装済みという意味ではありません。任意ノードのパラメータ編集などは今後の拡張です。

## カメラと較正

「設定」→「カメラ撮影設定」で対応解像度と内部較正YAMLを選び、保存後にカメラを再起動します。内部較正は9×6交点・25 mmマスのチェッカーボードを使用します。解像度ごとに較正を保存し、サイズが異なる較正は適用しません。

このPCでは1280×720で横方向の撮影範囲が広がることを確認しました。機種ごとの画角は実機で確認してください。外部較正GUIから撮影設定とHSV調整も行えます。色設定を既存のボール認識に反映するには認識ノードを再起動します。

外部較正・投影パッケージは次のようにビルドします。

```bash
source /opt/ros/jazzy/setup.bash
colcon build --base-paths real/src --packages-select ball_auto_approach camera_lidar_calibration --symlink-install
```

## 安全性

実機駆動は明示操作と確認を必要とします。較正と実機駆動の同時起動を防止し、較正プログラムから移動指令は送信しません。停止・指令途絶への対処には既存の駆動側監視も使用します。GUIの停止ボタンは物理非常停止の代替にはなりません。管理外のプロセスは勝手に停止しません。

## 足回り駆動と自動接近

起動項目を「足回り駆動」に統合しました。「ボール自動接近（非駆動確認）」「自動接近・実機駆動」の個別項目はありません。

- ダッシュボードの「足回り駆動で自動接近を有効にする」がOFFなら、足回りは従来の手動操縦だけで起動します。カメラや較正結果を必要としません。
- ONなら、足回り起動時にJoy・カメラ・LiDAR・位置推定・接近コントローラーをまとめて起動します。スティックによる手動操縦と、L1保持＋△による接近を1つの駆動セッションで扱います。
- 自動接近の切り替えと設定変更は足回り停止中に行います。起動直後に自動接近は開始しません。○・L1解除・スティック操作で中止します。
- 自動接近の利用には「自動接近設定」で保存済み外部較正YAML、目標距離と確認済み最小距離を保存します。較正GUI・画像投影で先に認識を確認してください。

カメラの取り付けが動く状態では自動接近をOFFにします。固定・再較正後にONにしてください。初期状態はOFFで、このPCも2026-11-28のGUI変更時点でOFFにしました。共有設定はconfig/programs.yaml、PC固有の切り替えはlocal.yamlのvariables.MOTOR_AUTO_APPROACH（真偽値）に保存します。

CANがDOWN・未検出・未確認の場合は足回りの起動ボタンを無効化し、起動要求も拒否します。CAN状態は直近の検査結果を使用し、ERROR-ACTIVEを確認します。依存センサーの起動中にCANが利用できなくなった場合も駆動を開始しません。駆動中のCAN利用不可や依存プログラム終了時は足回りを停止します。CANの再有効化と駆動の再開始は明示操作です。

自動接近では保存済み外部変換と球検出条件を使用し、初回の速度は最大30 mm/sに制限します。カメラのTFは追加配信しません。カメラ認識、LiDAR追跡、時刻・Joyの途絶、障害物、時間超過で停止します。接近プロセスの異常終了時は統合セッション全体を終了し、既存の駆動側停止ウォッチドッグも継続して使用します。実機の動作を伴うため、周囲と物理非常停止を確認してから足回りを起動してください。

認識画像は/camera_lidar/approach_image、位置は/ball/estimate、状態は/ball/stateです。球表面距離はLiDAR原点から球表面までの3次元最短距離です。障害物検査には前方フィルター外も含む全スキャンを使用します。機体部品の反射を除外する場合は、実物と照合した車体内部の小範囲だけをrobot_geometry.lidar_self_filter_box_m（[x最小,x最大,y最小,y最大]、m）で指定します。車体外の範囲は拒否します。このPCの確認済み範囲は機体中心の前後±60 mm・左40〜90 mmです。取り付け変更時は再確認してください。

## RViz2でLiDARを確認する

実機のRViz2を起動すると、必要なLiDARも依存順に起動します。初期設定はFixed Frame=laser、LaserScan=/scan、Best Effortです。地図やbase_linkとのTFがなくても点群を表示できます。シミュレーションのRViz2はGazeboに依存し、同じ設定とシミュレーション時刻を使用します。

地図を表示するときはRViz内でFixed Frameをmapに切り替え、Map表示を有効にします。地図作成ノードと対応するTFは別途必要です。

## AMT102-CANエンコーダー2台の値を表示する

`amt102_can`をビルド後にControl Centerを再起動し、「エンコーダーCANを有効化」を押して「AMT102 エンコーダー（2台）」を起動します。ダッシュボードとデバイス管理に、検出したchごとの角度・受信開始からの相対回転数・受信Hz・同期と異常履歴の状態を表示します。モーター駆動を起動する必要はありません。

2台を異なるchに設定してください。未受信・受信途絶と、位置が変化しない正常な受信を区別します。起動時のfault bitは再起動履歴でも立つため、詳細を読み出し、再起動履歴だけなら「再起動履歴のみ（受信正常）」を緑で表示します。その他の異常履歴や詳細確認待ちは警告として表示します。この受信機能はCAN設定書込み・SYNC・モーター指令を送信しません。

詳しい単位、ROSトピック、CPRの前提、接続確認は[エンコーダーREADME](../real/src/amt102_can/README.md)を参照してください。このPCではWeActのslcan0上でCH1・CH2の実機周期データと設定読出し応答を確認しました。両方の設定送信周波数は200 Hzで、確認時の異常詳細は再起動履歴bit0のみです。読み取り専用ノードのカーネルフィルターではCAN_ERR_FLAGを通常データ用マスクに含めず、全8chの標準データフレームを通します。

USB-CANは別々に扱います。「モーターCANを有効化」はDM3519のcan0、「エンコーダーCANを有効化」はAMT102のWeActから作るslcan0を操作します。エンコーダーの値の見出しにも実際の受信インターフェースを表示します。WeAct側はPC固有のENCODER_CAN_PORTに/dev/serial/by-id/の固定名を保存し、ttyACMの番号変化に対応します。詳細はエンコーダーREADMEを参照してください。

エンコーダーの角度表示はROSグラフの定期更新から分離し、50 Hzの位置配信を受信のたびに反映します。角度・相対回転数を細かく表示し、「エンコーダー読取開始／停止」で読取状態を切り替えます。CANがUPでも読取ノードが停止中なら値は表示されません。停止中・受信待ち・受信途絶を区別して表示します。起動時からエンコーダーの値を表示する場合はmain.pyに--encodersを付けると、実機モードで読取を開始します。モーターは起動しません。

表示経路のテストはtests/encoder_motion.pyです。CANに接続しない模擬8chをROS配信し、監視プロセスを通してQtの角度文字列が更新すること、受信停止で古い値の表示を止めること、再開後に復帰することを確認します。

実機モードの「RViz2（エンコーダー）」からCH1・CH2の矢印による回転表示を起動できます。エンコーダー読み取りも起動し、LiDARとは別の専用ウィンドウを開きます。表示は実機の取り付け寸法を含まない模式図です。main.py --encoder-rvizでも実機モードで読み取り・表示をまとめて開始できます。
# AMTエンコーダーによる指定距離移動

CH2を前後、CH1を左右の計測に使用します。車輪径50mm・直結（1:1）で、1回転は約157.08mmです。

1. 足回りを停止し、機体を手で前進・左移動させて、それぞれCH2・CH1の相対回転数が増えるか減るかを確認します。
2. 実機画面の「指定距離移動設定」で増減方向と距離（10〜2000mm、初期100mm）を指定し、エンコーダー使用を有効にして保存します。未確認の方向では有効にできません。
3. 足回り駆動を起動します。コントローラー・エンコーダー読取・IMUが依存プログラムとして起動します。中立でL1を離して押し直し、L1保持中に十字キーを押すと、その方向へ指定距離移動します。
4. L1解除、○ボタン、スティック操作で中止します。再操作はL1の押し直しが必要です。

L1解除の判定は手動・指定距離移動ともに既存の100ms連続OFF確認を使います。短いOFF入力だけでは指定距離移動を中止しません。入力受信が150ms途絶えた場合は別途停止します。ログの `L1 released (100ms confirmed)`、`controller input timeout (150ms)`、`stick moved` で停止理由を区別できます。入力再生テストは `python3 ros2_control_center/tests/controller_release.py` で実行でき、CANやモーターは使用しません。

目標手前の減速で摩擦に負ける場合に備え、最低移動速度の初期値を30mm/sにしています。GUIから0〜100mm/sで調整でき、0で無効です。加減速制限・停止距離による速度制限が優先され、負のPID出力に対して前進を強制しません。最高速度を超える設定は保存できません。進捗停止（1秒間に目標点までの距離が1mm減らない）と移動時間超過は別々に表示し、測定距離・残距離、進捗停止時の指令速度も記録します。最低速度を追加しても実際に動けない場合は従来どおり中止します。`python3 ros2_control_center/tests/encoder_stall.py` で、仮想的な摩擦による失速の再現、4方向の到達、拘束時の停止、時間超過の区別を確認できます。摩擦モデルの数値は実機測定値ではありません。

距離PID（P=2.0、I=0.1、D=0.25）でエンコーダーの移動距離を追従します。最大速度の初期値は250mm/s、加減速度は400mm/s²です。「指定距離移動設定」で最大速度30〜500mm/s、加減速度50〜1000mm/s²、各ゲインを変更できます。D項は移動速度に対する減衰で、フィルターを通して使用します。積分飽和を抑制し、停止距離に応じた速度制限で目標付近を減速します。距離の停止判定は目標まで5mm以内です。横ずれ許容値は初期50mmで、GUIから5〜100mmに変更できます（旧固定値は25mm）。前後移動では左右へのずれ、左右移動では前後へのずれを判定します。横ずれPDで開始位置を通る直線へ戻します。初期値は横ずれP=2.0、D=0.25、補正速度上限80mm/sで、GUIの「指定距離移動設定」から変更できます。補正速度上限0で補正を無効化します。3mm以内の横ずれには補正を出さず、ノイズによる往復を抑えます。移動方向と補正方向を合成した速度・加速度に上限をかけます。目標距離に達しても横ずれが5mmを超えていれば、進行方向の指令を減速して横方向を調整します。横ずれが許容値を超えた場合は補正中でも停止します。補正を無効化した場合も完了条件の横ずれ5mmは維持されます。逆方向5mm超過による停止とは別に判定・表示します。受信途絶（150ms）、読取再起動、エンコーダー基準のリセット、逆走、横ずれ、1秒間の進捗停止などでも中止します。進捗は進行方向の残距離と横ずれを合わせた目標点までの距離で判定し、終端の横方向調整も進捗として扱います。自動接近とは同時に有効にできません。

エンコーダー車輪の取付オフセットは未較正のため、回転を補正した位置推定には未対応です。IMUの姿勢変化が約1.7°を超えると中止します。距離設定は利用者別の `~/.config/ros2-control-center/encoder_distance.yaml`（XDG_CONFIG_HOME対応）に保存します。

この設定を無効にした場合は従来の手動操縦に戻ります。従来モードの十字キーは既存の1m移動処理であり、ここで指定した距離は適用されません。

模擬データで距離換算・完了判定・停止条件、GUI保存、起動依存関係、独立ウォッチドッグによる停止を検証しています。さらに4方向・5種類の目標距離・3種類の駆動ゲインの計60条件で、エンコーダー量子化と駆動遅延を含む閉ループ追従、速度・加速度・積分上限を確認しています。ゲインは実機未調整の初期値です。既存の設定ファイルに速度・ゲインがない場合も新しい初期値を使います。GUIの調整画面を更新するにはアプリを再起動してください。制御設定は足回り起動時に読み込み、実行中には変更しません。実機での距離精度・方向・制動距離は未確認です。初回は駆動輪を浮かせた状態などで方向と停止を確認し、物理非常停止を用意してください。

横ずれ補正の模擬検証は `python3 ros2_control_center/tests/encoder_cross_track.py` で実行できます。4方向×左右2種類の斜行傾向×外乱の有無の16条件で、量子化されたエンコーダーと駆動遅延を使って到達・横ずれ補正・速度/加速度制限・逸脱停止を確認しています。実機での補正ゲインと最低速度の調整は未確認です。
