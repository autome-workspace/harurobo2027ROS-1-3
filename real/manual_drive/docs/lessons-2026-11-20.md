## 既知の問題点（残件）

1. **駆動側の自力停止なし（実測済み）**。PCプロセス異常はウォッチドッグで約0.5〜1秒停止だが、**PC自体の死亡・USB-CAN物理断は手動非常停止のみ**が対策。計画の「独立遮断回路」は未整備。
2. **`TIMEOUT` の単位・仕様は未確認**（書込は行っていない）。
3. **車輪半径・機体寸法・装着軸は未計測**。機体速度は概算。4輪運動学ヘッダ（`wheel_kinematics.hpp`）は実装済みだが**駆動には未接続**（現状は既存ミキシング）。
4. **ヨー保持は継続走行モードに未統合**（統合ベンチまで）。ゲイン（Kp=0.5/Kd=0）未調整。IMU出力は約990Hzのまま（計画の200Hz化は未実施）。
5. **LiPoのS数未確認**。7Sは過電圧リスクのため使用禁止と伝達済み。バッテリー直近のヒューズ等を推奨。
6. **停止距離は未実測**（指令停止と物理停止を分けた計測が計画上必要）。
7. CANable再列挙後のバースト欠落の根因は不明（FW側。1.5ms送信間隔で回避）。
8. IMUの長期静止ドリフト、USB抜去復帰の実機試験は未実施。
9. 速度6.6 rad/sは定格内だが、**床面負荷での連続使用時の温度・電流の実測はまだ**。

## ハマった点（再発防止）

1. **`ros2 run` のノード名不一致**：paramsファイルの `game_controller:` セクションに合わず `autorepeat_rate` がデフォルト0 → DS4のidle報文停止のたび `/joy` 途絶 → 走行中の勝手な停止。**`-r __node:=game_controller` で解決**。launch経由では最初から正常。
2. **CANableのバースト欠落**：USB再列挙後、フレーム間隔なしの連続送信で3本目以降がサイレントに落ちる（バスエラー計数0）。**1.5ms以上の送信間隔**で全台応答。全送信経路にpacing必須。
3. **パッチの適用確認を怠ると事故る**：送信間隔パッチが文字列不一致で未適用のまま数試行無駄にした。**修正後は `grep` で適用を検証**。
4. **残存プロセスの重複**：段階Aのlaunchが残ったまま後段の試験を実施し、複数 publisher/旧バイナリのテレオプが混入して記録を汚染。**試験前に `pgrep` で一掃し、トピックごとに発行者数を確認**。
5. **「発行者数1」は実データを保証しない**（トピック広告だけでも1になる）。**`ros2 topic echo --once` で実データ確認を必須に**。起動直後は検出遅れで0に見えることもある→数秒待つ。
6. **`PYTHONPATH=... python3` はROSのPYTHONPATHを上書き**して `rclpy` import失敗。プレフィックス代入は使わない（スクリプトの同階層importは自動）。
7. **SSHコマンドのヒアドキュメント構造ミス**：終端文字の後のコマンドがローカル実行になり、リモートにファイルだけ残る事故を繰り返した。複数行コマンドは `bash -s` にまとめる。
8. **`pkill -f` の自己一致**：パターンがsshラッパ自身のコマンド行に一致して自殺（exit 255）。ブラケットtrick（`nod[e]`）を使う。exit 255が出たら状態を再確認する。
9. **許可時間の上書きが効いていなかった**：`InputGate.expire` が3.0を直書きで `PERMIT=10` の上書きが無効。クラス属性化して解決。
10. **速度上限の保護値が固定1 rad/s**：上限5 rad/sで即異常停止。「一瞬だけ動いて停止」の原因。保護値は上限に連動させた。
11. **停止確認が過渡応答を拒否**：無効化直後、ゼロ指令への返信（まだstate=1）と無効化への返信が混ざり異常判定。**全台のstate=0を時間内に待つ方式**に変更。
12. **再許可は「両スティック中立でL1解放→押下」**。スティック倒したままのL1再押下では永久に再許可しない（仕様どおりだが指示文が重要）。
13. **USBハブの脱落**でDS4/IMUが消えた。なお入力途絶の真因は上記1.なので、**ポートの入れ替え自体は不要だった**（WiFiドングルのハブ移設はSSH不安定化要因になったので直挿し推奨）。
14. **DS4は抜き差し後にスリープすることがある**：PSボタン押下で復帰。ログが空でも `ros2run` 子プロセスのバッファが失われただけのことがある。
15. **時間窓とチャット指示のずれ**：60秒窓に操作が間に合わない事故が複数回。窓は120秒に、許可は10秒に拡大し、入力実データを確認してから案内。
16. **Bluetooth切替は未実施**：切り替える場合は計画どおり有線と同じ受入（マッピング・gap記録・切断停止）を最初からやり直すこと。

## 起動・停止スクリプト

```bash
cd ~/ros2-poc-manual-drive
./scripts/start_manual_drive.sh   # can0確認→joy（ノード名修正済み）→ウォッチドッグ→manual_drive。二重起動防止・/joy実データ確認つき
./scripts/stop_manual_drive.sh    # SIGINTで安全停止（ウォッチドッグはdoneハンドシェイクで終了）
```

can0が停止している場合は再設定用のsudoコマンドが表示される。**終了は必ずこのスクリプトかSIGINT**（SIGKILLはウォッチドッグの停止バーストを招く）。ROSのsetup.bashは未設定変数を使うため、スクリプト側の `set -u` は使わない。
