# 春ロボ ROS 2 Jazzy 手動走行 実装計画

## 1. 完成条件

Ubuntu 24.04の機体搭載PCを想定する。DualShock 4で前後・左右・斜め移動とその場旋回ができ、旋回入力を離して平行移動するときにDM-IMU-L1で機首方向を保持できる。デッドマン解除、入力途絶、CAN異常で停止し、復旧後は操作者が再許可する。初回はDS4をUSB有線で使用し、必要なら同じ受入試験をBluetoothで繰り返す。LiDAR、追加エンコーダー、自己位置推定、自動走行、フィールド基準操作は後続フェーズとする。

## 2. ノードと入出力

| ノード | 入力 | 出力・責務 |
|---|---|---|
| joy / game_controller_node | DS4 | /joy (sensor_msgs/msg/Joy)。SDLマッピングで受信、自動再発行は50 Hzから開始 |
| harurobo_teleop | /joy | /cmd_vel/manual (geometry_msgs/msg/TwistStamped, base_link)、デッドマンと中立判定、再許可操作 |
| DM-IMU-L1ドライバ | USB仮想シリアル | /imu/data (sensor_msgs/msg/Imu, imu_link)、診断 |
| harurobo_base | 手動速度・許可状態、IMU、CANフィードバック | ヨー補正、逆運動学、4輪の速度制御、SocketCAN送受信、/diagnostics |
| harurobo_bringup | 機体YAML | 一括起動、静的TF base_link → imu_link |

制御系はC++（rclcpp）、launchはPythonを想定。CAN送信は harurobo_base に集約する。手動指令は速度をm/s、角速度をrad/sで表し、将来はこの入力境界に手動・自動指令の切替を追加する。機体制御周期はまず100 Hz。制御タイマーと途絶監視は単調時計を使用し、受信キューを小さく保つ。Joyの自動再発行を利用する場合も、USB抜去・Bluetooth切断時に保持入力が再発行され続けないことを実機で確認する。残る場合は接続監視を許可信号に組み込む。

## 3. ハードウェアの立ち上げ

1. DM3519本体とドライバのラベル・型番・FWを記録する。対応モード、CAN/CAN FD、ビットレート、指令・応答ID、データ形式、速度の単位と軸（モーター軸か出力軸か）、電流制限、通信タイムアウト、停止時のブレーキ／フリー動作を、対象版の資料と単輪で照合する。DM3519-1ECの公開サンプル対応に関する報告があるため、機種未確認の汎用DMフレームやC620設定を流用しない。
2. USB-CANはLinuxでSocketCANの can0 として認識する機種を前提とする。Classic CAN対応を実機で確認できれば手持ちのcandleLight系を候補にできる。CAN FDが必要ならFD対応機を使用する。メーカー純正のUSB変換器はUSBシリアルを使うため、SocketCANとの互換性を前提にしない。CANは線形に配線し、両端のみ120Ω終端、電源OFF時にCAN_H–CAN_L間の総合抵抗を確認する。
3. 1台ずつ設定してアドレスを割り当て、4台接続後に指令先と返信識別が一意であることを確認する。グループ指令方式ならIDとフレーム内スロットを台帳に記録する。ip -details -statistics link show can0 と candump で応答周期・CANエラーを記録する。
4. 最初は車輪を浮かせ、低電流・低速度で正逆転と停止を確認する。内部速度指令が使えれば採用する。電流／トルク指令のみの場合は、速度フィードバックを確認してから輪ごとの速度PI・出力クランプを実装し、単輪で調整する。最大バス電流、配線・保護、回生時の電圧上昇を確認する。
5. 通信断時に駆動側が自力で停止する機能を確認する。実装できなければ、PCのハートビート途絶で駆動を遮断できる独立した回路等を用意するまで床上走行に進まない。物理非常停止はPCとUSB通信から独立させ、駆動電源遮断等の設計に合わせて停止距離を実測する。

## 4. 手動操作と4輪運動学

| 操作 | 初期割当 |
|---|---|
| 左スティック上下／左右 | 前後 vx、左右 vy |
| 右スティック左右 | 旋回 wz |
| L1押下中 | 運転許可。中立でいったん離し、押し直すと再許可 |

Joyの軸・符号・ボタンは ros2 topic echo /joy で確認する。軸デッドゾーンは0.08を初期値とし、並進スティックはベクトル長を制限して斜め入力の速度増加を防ぐ。床上初期値は並進0.25 m/s、旋回0.5 rad/s程度とし、機械条件・停止試験に応じて下げる。通常指令に加速度制限をかけ、異常停止は通常の入力ランプを経由せず検証済みの停止方式へ移行する。

座標は base_link の前方を+x、左を+y、上を+z。左前・右前・左後・右後それぞれの車輪中心 (xᵢ,yᵢ)、正方向の駆動単位ベクトル (tₓᵢ,tᵧᵢ)、有効半径 rᵢ、モーター正方向と車輪正方向の対応を実測してYAMLに入れる。オムニのローラーによる自由方向は駆動方向の定義と区別する。

    wheel_rad_s[i] = (tx[i]*(vx - wz*y[i]) + ty[i]*(vy + wz*x[i])) / radius[i]

モーター指令の符号・減速比・単位変換はCAN境界で適用する。出力軸基準の指令には減速比を二重に掛けない。逆運動学行列がランク3であることを確認し、いずれかの輪が上限を超える場合は全輪を同率で縮小する。前進・左移動・反時計回りのテストベクトルについて、実装前に車輪ごとの正負を実機図と照合する。

## 5. IMUとヨー角保持

- DM-IMU-L1はUSBデータケーブルで接続し、実機の /dev/serial/by-id/ を設定する。CoRE2026実装の921600 baud、200 Hzを検証開始値とし、実機FWと出力設定を確認する。公開ドライバをJazzyでビルド・受信試験し、採用時は版を固定する。
- IMUを剛体固定して静止校正する。/imu/dataはROS座標・SI単位に統一し、ドライバ側の軸変換と静的TFを照合する。機体を手で反時計回りに回してyawとgyro_zの符号を確認する。Quaternionの正規化、時刻、欠落、静止時ドリフトを記録し、USB再接続前のサンプルは破棄する。
- 旋回スティック操作中は手動wzを優先する。旋回入力を離れた際は減速中にyaw目標を現在角へ追従させ、角速度が落ち着いた時点で目標角を捕捉する。平行移動中は wrap(目標yaw − 現在yaw) × Kp − Kd × gyro_z を補正角速度として出す。Kpのみ、出力上限0.2 rad/s程度から始め、必要に応じてKdを追加する。デッドマン解除時や両スティック中立時はゼロ指令とし、目標を解除して静止中の意図しない旋回を防ぐ。
- 補正ありモードでIMUが途絶したら停止し、異常を保持する。補正なしで走る場合は停止状態で明示的に選択し、再許可する。6軸IMUのyawは相対角として扱い、長時間のドリフトは静止時ログで把握する。

## 6. 停止と再許可

| 条件 | 動作 |
|---|---|
| 起動直後・プロセス再起動 | 駆動許可なし。手動入力・CANが正常、補正ありの場合はIMUも正常になってから中立・L1押し直しを受け付ける |
| L1解除 | 次の制御周期に停止指令。押し直し前に中立を要求する |
| Joy／手動指令途絶 | タイムアウト150 msを初期値とし、有効な許可・指令の組が揃わなければ全輪停止 |
| IMU途絶（補正あり） | タイムアウト100 msを初期値として停止、異常保持 |
| CAN bus-off、送信異常、任意の1輪の故障・応答途絶 | 全輪停止へ遷移。応答途絶の初期値は100 ms、確認済み応答周期に合わせて調整。通信が生きている場合は停止指令を送る |
| PC停止・USB-CAN抜去 | 駆動側の通信タイムアウトまたは独立遮断で停止。停止遷移の目標は入力消失から250 ms以内とし、実測で確定 |
| 回復後 | 古い指令を破棄し、正常状態・中立・L1押し直しを確認する。CANリンク再起動だけで走行を再開しない |

タイムアウト値は試験用の暫定値。停止指令が出るまでの時間と、機体が物理的に止まるまでの時間・距離を分けて測る。電流指令ゼロ、速度指令ゼロ、駆動無効は挙動が異なるため、実機で検証した停止方法を採用する。

## 7. 実装順序と受入試験

| 段階 | 実装 | 次に進む条件 |
|---|---|---|
| A | DS4入力・速度変換・許可状態。モーター未接続で検証 | 入力と符号が正しく、起動時・解除時・切断時に非許可となる |
| B | DM3519×1とSocketCAN。指令、フィードバック、停止を確立 | 正逆転、指令量と速度の換算、USB-CAN抜去・PC停止時のローカル停止を実測 |
| C | 4輪運動学とCAN統合。浮かせて試験後、床上を低速で走行 | 前後・左右・斜め・旋回、全輪の速度制限、1輪の異常時の全輪停止を確認 |
| D | IMU単体とヨー角保持 | 補正の向き、旋回入力優先、停止時無動作を確認。補正あり／なしで同じ低速直進を各3回以上行い、最大yaw偏差と終点偏差を記録する。yaw偏差を減らし、持続振動がないことを確認 |
| E | 一括起動、切断と復帰、操作手順 | DS4・IMU・USB-CANの抜去、プロセス強制終了、物理非常停止を順に試験。復帰・再起動時に再許可まで動かないことを確認 |

リポジトリには bringup launch、機体別YAML、ドライバ型番・FW・CAN割当表、停止試験ログと操作手順を残す。YAMLの主項目はCANインターフェース／通信条件、4輪配置・符号・速度上限、DS4割当、IMUポート、補正ゲイン、監視閾値。実装前に確定する値は車輪配置・半径、DM3519ドライバ型番・FW、USB-CAN型番、電源・停止回路の構成。
